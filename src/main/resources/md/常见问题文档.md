## 启动相关问题

### Q1: 应用启动失败，提示端口被占用
**问题现象**：
```
Web server failed to start. Port 8080 was already in use.
```

**解决方案**：
1. **查找占用端口的进程**：
   ```bash
   # macOS/Linux
   lsof -i :8080
   
   # Windows
   netstat -ano | findstr :8080
   ```

2. **终止占用进程**：
   ```bash
   # 根据PID终止进程
   kill -9 <PID>
   ```

3. **修改应用端口**：
   ```yaml
   # application.yml
   server:
     port: 8081
   ```

### Q2: 应用启动时出现Bean创建失败
**问题现象**：
```
Error creating bean with name 'xxxService': Unsatisfied dependency
```

**排查步骤**：
1. **检查依赖注入**：确认@Autowired或@Resource注解是否正确
2. **检查组件扫描**：确认@ComponentScan路径是否包含相关类
3. **检查循环依赖**：使用@Lazy注解或重构代码避免循环依赖
4. **检查配置类**：确认@Configuration和@Bean配置是否正确

**解决方案**：
```java
// 使用@Lazy解决循环依赖
@Autowired
@Lazy
private UserService userService;

// 或使用构造函数注入
@Service
public class UserServiceImpl {
    private final RoleService roleService;
    
    public UserServiceImpl(RoleService roleService) {
        this.roleService = roleService;
    }
}
```

### Q3: 内存溢出错误（OutOfMemoryError）
**问题现象**：
```
java.lang.OutOfMemoryError: Java heap space
```

**解决方案**：
1. **调整JVM参数**：
   ```bash
   # 启动参数
   java -Xms512m -Xmx2048m -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=512m -jar app.jar
   ```

2. **分析内存使用**：
   ```bash
   # 生成堆转储文件
   jmap -dump:format=b,file=heapdump.hprof <pid>
   
   # 使用MAT或VisualVM分析
   ```

3. **优化代码**：
   - 及时关闭资源（数据库连接、文件流等）
   - 避免大对象长时间持有
   - 使用对象池技术

## 数据库连接问题

### Q4: 数据库连接超时
**问题现象**：
```
com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**解决方案**：
1. **检查数据库配置**：
   ```yaml
   spring:
     datasource:
       url: jdbc:mysql://localhost:3306/zboot?useSSL=false&serverTimezone=GMT%2B8
       username: root
       password: password
       hikari:
         connection-timeout: 30000
         idle-timeout: 600000
         max-lifetime: 1500000
         maximum-pool-size: 20
         minimum-idle: 5
   ```

2. **检查网络连接**：
   ```bash
   # 测试数据库连接
   telnet localhost 3306
   
   # 或使用ping
   ping database-host
   ```

3. **检查防火墙设置**：确保数据库端口未被防火墙阻止

### Q5: 连接池耗尽
**问题现象**：
```
HikariPool-1 - Connection is not available, request timed out after 30000ms
```

**解决方案**：
1. **调整连接池配置**：
   ```yaml
   spring:
     datasource:
       hikari:
         maximum-pool-size: 50  # 增加最大连接数
         minimum-idle: 10       # 增加最小空闲连接
         connection-timeout: 60000  # 增加连接超时时间
         leak-detection-threshold: 60000  # 启用连接泄漏检测
   ```

2. **检查连接泄漏**：
   - 确保所有数据库操作都正确关闭连接
   - 使用try-with-resources语句
   - 检查事务是否正确提交或回滚

3. **优化SQL查询**：
   - 添加适当的索引
   - 优化慢查询
   - 避免长时间运行的事务

## Redis连接问题

### Q6: Redis连接失败
**问题现象**：
```
Unable to connect to Redis; nested exception is io.lettuce.core.RedisConnectionException
```

**解决方案**：
1. **检查Redis服务状态**：
   ```bash
   # 检查Redis是否运行
   redis-cli ping
   
   # 启动Redis服务
   redis-server
   ```

2. **检查连接配置**：
   ```yaml
   spring:
     data:
       redis:
         host: localhost
         port: 6379
         password: your-password
         timeout: 10000ms
         lettuce:
           pool:
             max-active: 8
             max-wait: -1ms
             max-idle: 8
             min-idle: 0
   ```

3. **检查网络和防火墙**：确保Redis端口6379可访问

### Q7: Redis序列化问题
**问题现象**：
```
Cannot deserialize; nested exception is org.springframework.core.serializer.support.SerializationFailedException
```

**解决方案**：
1. **检查序列化配置**：
   ```java
   @Configuration
   public class RedisConfig {
       @Bean
       public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory connectionFactory) {
           RedisTemplate<String, Object> template = new RedisTemplate<>();
           template.setConnectionFactory(connectionFactory);
           
           // 使用Jackson序列化
           Jackson2JsonRedisSerializer<Object> serializer = new Jackson2JsonRedisSerializer<>(Object.class);
           ObjectMapper om = new ObjectMapper();
           om.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
           om.activateDefaultTyping(LaissezFaireSubTypeValidator.instance, ObjectMapper.DefaultTyping.NON_FINAL);
           serializer.setObjectMapper(om);
           
           template.setKeySerializer(new StringRedisSerializer());
           template.setValueSerializer(serializer);
           template.setHashKeySerializer(new StringRedisSerializer());
           template.setHashValueSerializer(serializer);
           
           return template;
       }
   }
   ```

## 权限认证问题

### Q8: 用户登录失败
**问题现象**：
```
{
  "code": 401,
  "message": "用户名或密码错误"
}
```

**排查步骤**：
1. **检查用户信息**：确认用户名和密码是否正确
2. **检查密码加密**：确认密码加密方式是否一致
3. **检查用户状态**：确认用户是否被禁用或锁定
4. **检查数据库连接**：确认能正常查询用户表

**解决方案**：
```java
// 检查密码加密
@Service
public class AuthService {
    public boolean validatePassword(String rawPassword, String encodedPassword) {
        return passwordEncoder.matches(rawPassword, encodedPassword);
    }
}
```

### Q9: 权限验证失败
**问题现象**：
```
{
  "code": 403,
  "message": "权限不足"
}
```

**解决方案**：
1. **检查用户角色**：确认用户是否分配了正确的角色
2. **检查权限配置**：确认角色是否配置了相应的权限
3. **检查权限缓存**：清除并重新加载权限缓存
   ```java
   // 清除权限缓存
   @Autowired
   private RedisUtils redisUtils;
   
   public void clearUserPermissionCache(Long userId) {
       redisUtils.del("user:permission:" + userId);
   }
   ```

### Q10: Token过期或无效
**问题现象**：
```
{
  "code": 401,
  "message": "Token已过期"
}
```

**解决方案**：
1. **检查Token配置**：
   ```yaml
   sa-token:
     token-name: Authorization
     timeout: 2592000  # 30天
     activity-timeout: 1800  # 30分钟
     is-concurrent: true
     is-share: false
   ```

2. **实现Token刷新机制**：
   ```java
   @RestController
   public class AuthController {
       @PostMapping("/refresh-token")
       public R<String> refreshToken() {
           StpUtil.renewTimeout(7200); // 续期2小时
           return R.ok(StpUtil.getTokenValue());
       }
   }
   ```

## 性能优化问题

### Q11: 接口响应慢
**问题现象**：接口响应时间超过3秒

**排查步骤**：
1. **分析SQL性能**：
   ```sql
   -- 开启慢查询日志
   SET GLOBAL slow_query_log = 'ON';
   SET GLOBAL long_query_time = 1;
   
   -- 查看执行计划
   EXPLAIN SELECT * FROM user WHERE name = 'test';
   ```

2. **检查缓存使用**：
   ```java
   @Cacheable(value = "user", key = "#id")
   public User getUserById(Long id) {
       return userMapper.selectById(id);
   }
   ```

3. **优化数据库连接池**：
   ```yaml
   spring:
     datasource:
       hikari:
         maximum-pool-size: 50
         minimum-idle: 10
         connection-timeout: 30000
   ```

### Q12: 内存使用率过高
**解决方案**：
1. **JVM参数调优**：
   ```bash
   -Xms1024m -Xmx2048m
   -XX:+UseG1GC
   -XX:MaxGCPauseMillis=200
   -XX:+PrintGCDetails
   -XX:+PrintGCTimeStamps
   ```

2. **代码优化**：
   - 使用分页查询避免大结果集
   - 及时释放不用的对象引用
   - 使用StringBuilder代替字符串拼接

## 日志配置问题

### Q13: 日志不输出或输出异常
**解决方案**：
1. **检查日志配置**：
   ```yaml
   logging:
     level:
       com.iceeboot: DEBUG
       org.springframework: INFO
     pattern:
       console: "%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n"
       file: "%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n"
     file:
       name: logs/application.log
       max-size: 100MB
       max-history: 30
   ```

2. **检查logback配置**：
   ```xml
   <!-- logback-spring.xml -->
   <configuration>
       <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
           <encoder>
               <pattern>%d{yyyy-MM-dd HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n</pattern>
           </encoder>
       </appender>
       
       <root level="INFO">
           <appender-ref ref="CONSOLE"/>
       </root>
   </configuration>
   ```

### Q14: 数据库日志存储失败
**问题现象**：日志无法保存到数据库

**解决方案**：
1. **检查日志配置**：
   ```yaml
   iceeboot:
     log:
       enabled: true
       level: INFO
       async: true
       retention-days: 30
   ```

2. **检查数据库表结构**：确保日志表存在且结构正确

3. **检查权限**：确保数据库用户有插入日志表的权限

## 消息通知问题

### Q15: 邮件发送失败
**问题现象**：
```
MailSendException: Failed messages: javax.mail.SendFailedException
```

**解决方案**：
1. **检查SMTP配置**：
   ```yaml
   spring:
     mail:
       host: smtp.gmail.com
       port: 587
       username: your-email@gmail.com
       password: your-app-password
       properties:
         mail:
           smtp:
             auth: true
             starttls:
               enable: true
   ```

2. **测试SMTP连接**：
   ```java
   @Service
   public class EmailTestService {
       public boolean testSmtpConnection(EmailConfig config) {
           try {
               Properties props = new Properties();
               props.put("mail.smtp.host", config.getHost());
               props.put("mail.smtp.port", config.getPort());
               props.put("mail.smtp.auth", "true");
               
               Session session = Session.getInstance(props, new Authenticator() {
                   @Override
                   protected PasswordAuthentication getPasswordAuthentication() {
                       return new PasswordAuthentication(config.getUsername(), config.getPassword());
                   }
               });
               
               Transport transport = session.getTransport("smtp");
               transport.connect();
               transport.close();
               return true;
           } catch (Exception e) {
               log.error("SMTP连接测试失败", e);
               return false;
           }
       }
   }
   ```

### Q16: 短信发送失败
**问题现象**：短信发送返回错误码

**解决方案**：
1. **检查短信配置**：确认AccessKey、SecretKey、签名、模板等配置正确
2. **检查账户余额**：确认短信服务商账户有足够余额
3. **检查手机号格式**：确认手机号格式正确
4. **查看错误日志**：根据具体错误码查找解决方案

   curl -H "Authorization: Bearer your-api-key" \

**解决方案**：
1. **调整超时配置**：
   ```yaml
   spring:
     ai:
       openai:
         timeout: 60s
         max-retries: 3
   ```

2. **实现重试机制**：
   ```java
   @Retryable(value = {Exception.class}, maxAttempts = 3, backoff = @Backoff(delay = 1000))
   public String callAI(String prompt) {
       // AI调用逻辑
   }
   ```

public class CodeGeneratorTest {

## 监控运维问题

### Q23: 应用健康检查失败
**解决方案**：
1. **启用Actuator**：
   ```yaml
   management:
     endpoints:
       web:
         exposure:
           include: health,info,metrics
     endpoint:
       health:
         show-details: always
   ```

2. **检查健康检查端点**：
   ```bash
   curl http://localhost:8080/actuator/health
   ```

### Q24: JVM监控指标异常
**解决方案**：
1. **配置JVM监控**：
   ```bash
   -Dcom.sun.management.jmxremote
   -Dcom.sun.management.jmxremote.port=9999
   -Dcom.sun.management.jmxremote.authenticate=false
   -Dcom.sun.management.jmxremote.ssl=false
   ```

2. **使用监控工具**：
   - JConsole
   - VisualVM
   - Prometheus + Grafana

## 开发调试问题

### Q25: 热部署不生效
**解决方案**：
1. **添加devtools依赖**：
   ```xml
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-devtools</artifactId>
       <scope>runtime</scope>
       <optional>true</optional>
   </dependency>
   ```

2. **IDE配置**：
   - IDEA：启用"Build project automatically"
   - Eclipse：启用"Project > Build Automatically"

### Q26: 断点调试不生效
**解决方案**：
1. **检查调试配置**：确认以debug模式启动
2. **检查源码映射**：确认源码和运行的class文件一致
3. **检查断点位置**：确认断点设置在可执行代码行

## 总结

本文档涵盖了ZBoot项目开发和运维过程中的常见问题及解决方案。在遇到问题时，建议按照以下步骤进行排查：

1. **查看日志**：首先查看应用日志和错误堆栈
2. **检查配置**：确认相关配置是否正确
3. **验证环境**：确认运行环境是否正常
4. **逐步排查**：从简单到复杂，逐步缩小问题范围
5. **查阅文档**：参考官方文档和社区资源
6. **寻求帮助**：在社区或团队中寻求帮助

如果遇到本文档未涵盖的问题，建议：
- 详细记录问题现象和错误信息
