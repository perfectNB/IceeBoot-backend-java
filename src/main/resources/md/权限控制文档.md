# ZBoot 权限控制系统文档

## 1. 概述

ZBoot 采用基于 RBAC（Role-Based Access Control）模型的权限控制系统，结合 Sa-Token 框架和 Redis 缓存，实现了灵活、高效的权限管理机制。系统支持动态权限验证、多级权限控制和细粒度的接口权限管理。

## 2. 系统架构

### 2.1 核心组件

- **Sa-Token**: 轻量级权限认证框架，负责用户登录状态管理和基础权限验证
- **Redis**: 缓存用户权限信息，提升权限验证性能
- **权限拦截器**: 基于注解的权限验证拦截器
- **RBAC模型**: 用户-角色-权限三层权限模型

### 2.2 数据模型

```
用户(User) ←→ 用户角色关联(UserRole) ←→ 角色(Role) ←→ 角色权限关联(RolePermission) ←→ 权限(Permission)
```

## 3. 权限控制实现

### 3.1 权限注解 @RequirePermission

系统提供了 `@RequirePermission` 注解用于标记需要权限验证的接口：

```java
@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
@Documented
public @interface RequirePermission {
    
    /**
     * 权限编码数组，支持多个权限
     */
    String[] value() default {};
    
    /**
     * 单个权限编码
     */
    String code() default "";
    
    /**
     * 权限描述
     */
    String description() default "";
    
    /**
     * 是否需要所有权限都满足
     * true: AND逻辑，false: OR逻辑
     */
    boolean requireAll() default false;
    
    /**
     * 是否启用动态权限查询
     * true: 从Redis中根据URL动态查询权限
     * false: 使用注解中指定的权限编码
     */
    boolean dynamic() default false;
}
```

### 3.2 使用示例

#### 静态权限验证

```java
@RestController
@RequestMapping("/v1/users")
public class UserController {
    
    // 单个权限验证
    @GetMapping
    @RequirePermission(code = "user:list")
    public R<List<User>> getUserList() {
        // 业务逻辑
    }
    
    // 多个权限验证（OR逻辑）
    @PostMapping

    public R<Void> createUser(@RequestBody UserDTO dto) {
        // 业务逻辑
    }
    
    // 多个权限验证（AND逻辑）
    @DeleteMapping
    @RequirePermission(value = {"user:delete", "admin:super"}, requireAll = true)
    public R<Void> deleteUser(@RequestParam Long id) {
        // 业务逻辑
    }
}
```

### 3.3 权限拦截器实现

`PermissionInterceptor` 是权限验证的核心组件，实现了基于注解的权限拦截：

```java
@Component
public class PermissionInterceptor implements HandlerInterceptor {
    
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws Exception {
        // 1. 检查是否为方法处理器
        if (!(handler instanceof HandlerMethod)) {
            return true;
        }
        
        // 2. 获取权限注解
        HandlerMethod handlerMethod = (HandlerMethod) handler;
        RequirePermission annotation = getPermissionAnnotation(handlerMethod);
        
        // 3. 无权限注解直接放行
        if (annotation == null) {
            return true;
        }
        
        // 4. 获取当前用户ID
        Long userId = TokenUtils.getCurrentUserId();
        if (userId == null) {
            throw new NotPermissionException("用户未登录");
        }
        
        // 5. 获取需要验证的权限
        String[] requiredPermissions = getRequiredPermissions(annotation, request);
        
        // 6. 验证用户权限
        return validateUserPermissions(userId, requiredPermissions, annotation.requireAll());
    }
}
```

## 4. 用户认证流程

### 4.1 登录流程

```java
@PostMapping("/login")
public R<LoginVO> login(@RequestBody LoginDTO loginDTO) {
    // 1. 参数校验
    validateLoginParams(loginDTO);
    
    // 2. 查询用户信息
    UserDO user = userService.getUserByUsername(loginDTO.getUsername());
    
    // 3. 验证用户状态和密码
    validateUserAndPassword(user, loginDTO.getPassword());
    
    // 4. 生成Token
    StpUtil.login(user.getId());
    String accessToken = StpUtil.getTokenValue();
    
    // 5. 缓存用户角色信息
    cacheUserRoles(user.getId());
    
    // 6. 返回登录信息
    return buildLoginResponse(accessToken, user);
}
```

### 5.3 缓存初始化

系统启动时会自动初始化角色权限缓存：

```java
@Service
public class RoleCacheInitService implements ApplicationRunner {
    
    @Override
    public void run(ApplicationArguments args) throws Exception {
        log.info("角色缓存初始化服务启动，开始加载角色权限和菜单缓存...");
        
        // 初始化角色权限和菜单缓存
        initRoleCache();
        
        log.info("角色缓存初始化完成");
    }
    
    private void initRoleCache() {
        // 1. 获取所有激活角色
        List<RoleDO> activeRoles = roleService.getActiveRoles();
        
        // 2. 为每个角色初始化权限缓存
        for (RoleDO role : activeRoles) {
            initRolePermissionCache(role.getId());
            initRoleMenuCache(role.getId());
        }
    }
}
```

## 6. 动态权限管理

### 6.1 URL权限映射

系统支持将URL与权限编码进行动态映射，实现灵活的权限控制：

```java
// 设置URL权限映射
authCacheService.setUrlPermissions("/v1/users/page", Arrays.asList("user:list", "user:view"));

// 获取URL对应的权限
List<String> permissions = authCacheService.getUrlPermissions("/v1/users/page");
```

### 6.2 权限验证逻辑

动态权限验证的核心逻辑：

```java
private String[] getRequiredPermissions(RequirePermission annotation, HttpServletRequest request) {
    if (annotation.dynamic()) {
        // 动态权限：从Redis中根据URL获取权限编码
        String requestUrl = getRequestUrl(request);
        List<String> urlPermissions = authCacheService.getUrlPermissions(requestUrl);
        return urlPermissions.toArray(new String[0]);
    } else {
        // 静态权限：使用注解中指定的权限编码
        return getStaticPermissions(annotation);
    }
}
```

## 8. 异常处理

### 8.1 权限异常处理

系统提供了全局异常处理器来处理权限相关异常：

```java
@RestControllerAdvice
public class GlobalExceptionHandler {
    
    /**
     * 权限不足异常处理
     */
    @ExceptionHandler(NotPermissionException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public R<Void> handleNotPermissionException(NotPermissionException e, HttpServletRequest request) {
        String requestURI = request.getRequestURI();
        log.error("请求地址'{}',权限码校验失败'{}'", requestURI, e.getMessage());
        return R.forbidden(ResponseMessage.FORBIDDEN);
    }
    
    /**
     * 角色权限异常处理
     */
    @ExceptionHandler(NotRoleException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public R<Void> handleNotRoleException(NotRoleException e, HttpServletRequest request) {
        String requestURI = request.getRequestURI();
        log.error("请求地址'{}',角色权限校验失败'{}'", requestURI, e.getMessage());
        return R.forbidden(ResponseMessage.FORBIDDEN);
    }
}
```

### 8.2 常见异常类型

- `NotPermissionException`: 权限不足异常
- `NotRoleException`: 角色权限异常
- `NotLoginException`: 未登录异常
- `DisableServiceException`: 服务被禁用异常

## 9. 最佳实践

### 9.1 权限设计原则

1. **最小权限原则**: 用户只拥有完成工作所需的最小权限
2. **权限分离**: 不同功能模块的权限应该分离
3. **角色层次化**: 建立清晰的角色层次结构
4. **权限粒度适中**: 权限粒度既不能太粗也不能太细

### 9.2 权限编码规范

```java
// 模块:操作 格式
"user:list"     // 用户列表查看
"user:create"   // 用户创建
"user:update"   // 用户更新
"user:delete"   // 用户删除
"user:export"   // 用户导出

// 层次化权限
"system:user:list"      // 系统管理-用户管理-列表查看
"system:role:assign"    // 系统管理-角色管理-权限分配
```

### 9.3 性能优化建议

1. **合理使用缓存**: 将用户权限信息缓存到Redis中
2. **批量权限验证**: 对于需要多个权限的操作，使用批量验证
3. **权限预加载**: 在用户登录时预加载权限信息
4. **缓存更新策略**: 权限变更时及时更新缓存

### 9.4 安全注意事项

1. **权限验证不能绕过**: 所有敏感操作都必须进行权限验证
2. **前后端权限一致**: 前端权限控制只是用户体验优化，后端必须有完整的权限验证
3. **权限日志记录**: 记录权限验证失败的日志，便于安全审计
4. **定期权限审查**: 定期审查用户权限，清理不必要的权限

## 10. 配置说明

### 10.1 Sa-Token配置

```yaml
sa-token:
  # token名称 (同时也是cookie名称)
  token-name: satoken
  # token有效期，单位s 默认30天, -1代表永不过期
  timeout: 2592000
  # token临时有效期 (指定时间内无操作就视为token过期) 单位: 秒
  activity-timeout: -1
  # 是否允许同一账号并发登录 (为true时允许一起登录, 为false时新登录挤掉旧登录)
  is-concurrent: true
  # 在多人登录同一账号时，是否共用一个token (为true时所有登录共用一个token, 为false时每次登录新建一个token)
  is-share: true
  # token风格
  token-style: uuid
  # 是否输出操作日志
  is-log: false
```

## 11. 总结

ZBoot 权限控制系统通过 RBAC 模型、Sa-Token 框架和 Redis 缓存的结合，实现了一套完整、灵活、高性能的权限管理方案。系统支持静态和动态两种权限验证方式，提供了丰富的权限管理接口，能够满足各种复杂的业务权限需求。

通过合理的权限设计和缓存策略，系统在保证安全性的同时，也具备了良好的性能表现。开发者可以根据具体业务需求，灵活配置和扩展权限控制功能。
