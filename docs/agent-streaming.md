# 智能体流式对话

对话使用 `POST /v1/agent-console/agents/by-code/{code}/stream`，沿用登录鉴权和 `{ input, sessionId }` 请求。响应为 `text/event-stream`，每帧 `event: progress`，`data` 是 AgentProgressVO。旧 `/invoke` 同步接口保留兼容。

执行事件包含根执行 ID、当前执行 ID、父执行 ID、智能体编码、有序序号、时间和状态。类型包括请求开始、运行阶段、模型开始、正文增量、工具开始/结束、智能体完成、整轮完成、失败和心跳。父、子智能体共享根执行和序号；前端分开展示子智能体摘要与主回复。模型实际返回的独立分析通道通过 REASONING_DELTA 实时展示，结束后保存 REASONING_FINISHED；每段最多保留 100000 字符，超出后明确提示截断。未返回分析通道的模型仅展示实际阶段和工具记录，不自动开启高耗时的思考模式。模型调用按轮次编号，工具被拒绝与执行失败使用独立状态提示。工具参数和结果经过脱敏并截断为 2000 字符摘要，完整正文在完成时校准。

模型正文增量立即推送，前端按短间隔合并渲染。用户消息发送后立即显示。执行中可停止；取消、超时或断线后会保留当前模型轮次已生成的正文。断开订阅会取消执行并释放会话租约，网络异常不会自动重发 POST。后端每 10 秒发心跳；前端连续 45 秒无事件时中断连接并同步数据库状态。

正文和分析的增量不重复入库，其余执行事件写入 `t_agent_progress`。已获授权的流中收到的实时过程直接显示；历史过程查询仍单独检查接口权限。历史过程通过 `GET /v1/agent-console/agents/{id}/sessions/{sessionId}/events?runId=...` 按需读取，查询按 agentId、登录 userId、sessionId 和根执行 ID 联合校验归属。无历史过程的旧对话显示空状态。正文和 SDK 日志上下文继续使用原会话存储。SDK 运行状态写入既有 `t_agent_session_state` 的 `runtime/*` 槽位，按外层 agentId、登录 userId、sessionId 绑定，以加密信封存储，并使用版本比较更新。运行状态可能含云实例临时凭据，因此更换主密钥时也需保留旧密钥的解密能力。

V009 建立过程表，V010 注册 `ai:agent:stream:api` 和 `ai:session:events:api` 两个接口权限，仅关联有效超级管理员；不改写已有迁移。重启后端自动升级，刷新登录权限后使用。现有取消接口仍使用 `ai:run:cancel`。

自动化回归使用模拟模型、内存数据库和 MockMvc，验证第一段输出在模型结束前到达、SSE 提前刷新、子智能体和工具事件、历史隔离、取消与断线清理、中文分片、鉴权及超时；不请求真实模型或创建收费云环境。

工作目录在交给 SDK 前统一为绝对、规范化路径，避免 `./` 导致技能资源被误判为越界并跳过；沙箱工具白名单采用实际注册名 `list_files`、`glob_files`、`grep_files`。E2B 延续 SDK 每轮释放自有实例的策略，释放后持久化状态不再保留已销毁实例 ID 和临时访问令牌，避免下轮先连接失效实例再重建。外部管理的实例保持原有生命周期。

E2B BETA1 的目录初始化命令会误将尚未创建的工作区作为 cwd。运行适配层仅在 `doSetupWorkspace` 期间使用已存在的 `/` 作为命令启动目录，目标路径与持久化状态保持不变；初始化完成或失败后恢复原目录行为，新建与恢复实例均适用。`E2bWorkspaceBootstrapTest` 使用内存 HTTP 拦截器验证新建/恢复、目录存在/不存在及后续命令的工作目录，不请求真实模型或云环境。

## 环境准备耗时优化

E2B 工作区同步改用 envd `/files` 的 multipart 文件上传：将 SDK 投影归档 gzip 压缩后一次上传，再用一次远程命令解压到原工作目录并清理临时文件。原生快照引用仍由 SDK 处理，不更改会话隔离与每轮释放策略。文件接口仅携带本实例 envd 临时令牌和执行用户身份，不转发平台 API Key，不跟随重定向，不回显上游错误正文。上传失败直接终止，不回退到逐 4000 字符启动进程的慢路径。日志记录归档大小、上传大小和上传耗时，不记录文件内容或凭据。

`deploy/e2b/Dockerfile` 在现有完整工具镜像基础上预装固定版本 `lunar-python==1.4.9`，保留原有浏览器、Node 和 CLI。构建时通过 `--build-arg BASE_IMAGE=<现有镜像>` 明确指定基础镜像，以 `deploy/e2b` 为构建上下文；注册表密码与 E2B Key 通过受控环境注入，不写入 Dockerfile 或镜像层。镜像发布后创建独立的新模板，验收 Shell、文件、浏览器和普通执行用户的依赖导入后再用于智能体。
