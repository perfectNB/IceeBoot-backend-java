# Agent 会话与数据库上下文

会话归属使用稳定的 `agentId + userId + sessionId`，用户身份来自登录上下文。相同用户可为同一 Agent 建立多个会话。每个会话创建时绑定发布快照，后续发布不会自动切换已有会话的版本；使用新版本请新建会话。

## 数据表

- `t_agent_session`：归属、发布版本、标题、更新时间以及执行租约。
- `t_agent_message`：用户输入、智能体输出、执行 ID 和状态，用于展示历史。历史接口每页最多 100 条，使用 `beforeId` 向前翻页；会话列表每页 50 条，使用 `offset` 翻页。
- `t_agent_session_state`：AgentScope 原生 JournalSessionLog 的原子存储，包含消息、工具调用与结果、状态快照和压缩上下文。使用数据库 revision 的条件更新和 SDK writer epoch 避免竞争覆盖。沙箱与非沙箱均显式使用此数据库日志，不依赖工作区文件恢复会话。沙箱内文件和进程本身仍受沙箱生命周期限制。

运行记录和模型调用账本继续保存在原表；消息通过 run_id 关联执行。跨节点会话执行租约在数据库中原子取得，存活期限为执行超时加 60 秒，只能由该次执行释放。节点异常退出时，租约到期后显示未完成消息为 INTERRUPTED，可重新调用；不自动重试外部工具副作用。

## API

- `GET /v1/agent-console/agents/{id}/sessions?offset=0`
- `POST /v1/agent-console/agents/{id}/sessions`，请求 `{ "title": "新对话" }`
- `GET /v1/agent-console/agents/{id}/sessions/{sessionId}/messages?beforeId=...`
- 原调用接口继续使用 `{ "input": "...", "sessionId": "..." }`，响应新增 sessionId。缺省时生成新会话，以兼容单次调用。

控制台保留超级管理员角色检查，三个新入口均有独立动态接口权限；任何会话读取都按当前用户和 Agent 校验归属。前端可选择历史会话、加载更早消息、继续提问和新建会话，失败输入保留以便重试。

## 升级

V006 创建三张会话表，V007 增加三个动态权限并仅为超级管理员关联。启动时自动执行；历史迁移文件不变。新表需要与其他 Agent 表一同备份，不应在日志中输出上下文内容。

旧执行记录保持可查。旧账本没有 sessionId，不能可靠还原为会话，因此不会自动伪造历史会话；此前 SDK 本地工作区上下文也不会自动导入。迁移完成后的新调用统一使用数据库会话。长期记忆 hooks/tools 继续关闭。

## 验证

回归覆盖：新运行实例和空工作目录下恢复历史、工具结果恢复、用户/Agent/会话隔离、发布版本固定、跨实例租约与 SDK writer 竞争、消息翻页、权限迁移幂等、前端连续发送、历史请求竞态与失败恢复。不调用真实模型或创建 E2B 沙箱。
