# Agent 模块维护与验证

## 服务边界

`IAgentPersistenceService` 保留为兼容门面，实现不再直接依赖 Mapper。数据分别交给模型、资源注册与明细、智能体定义、发布版本、执行账本五个 StorageService。公开服务方法承接事务，门面委派不改变跨表写入和发布锁的原子性。

五类资源保留独立的 IService、DTO、VO 和 Mapper，通过 `AbstractAgentResourceService` 复用类型校验、审计字段与 CRUD 事务；公共响应字段位于 `AgentResourceVO`。`AgentJsonCodec` 负责统一的 JSON 持久化契约。

## 主密钥轮换

新密文格式为 `enc:v2:<keyId>:<payload>`，继续使用 AES-256-GCM 和随机 nonce；可读取原 `enc:v1:` 密文。主密钥仍由部署环境注入，不通过管理接口传入。

1. 备份数据库和现有主密钥，停止旧配置的写入节点。多节点必须使用一致的当前密钥和解密密钥集合。
2. 配置新的 `AI_CONFIG_ENCRYPTION_KEY` 与新的 `AI_CONFIG_ENCRYPTION_KEY_ID`。标识仅包含字母、数字、下划线和短横线，最长 40 字符，不得使用保留值 `legacy`。同一标识不可代表不同密钥。
3. 将旧版本密钥注入 `iceeboot.agent.decryption-keys.<旧keyId>`。原 v1 密文通过 `AI_CONFIG_LEGACY_ENCRYPTION_KEY` 读取；未单独配置时兼容使用当前主密钥。任意历史 keyId 可通过部署配置或 `SPRING_APPLICATION_JSON` 注入，禁止提交真实值。
4. 部署并启动后，在模型连接页选择“轮换存储密文”，或调用 `POST /v1/agent-console/secrets/rotate`。接口仅允许拥有 `ai:secret:rotate` 权限的超级管理员。
5. 轮换在同一数据库事务内锁定并重加密模型 Key、工具/MCP/知识库请求头、Agent 环境变量及递归发布快照，覆盖逻辑删除的历史记录。任意一条密文无法读取时整体回滚。接口仅返回当前 keyId 和处理记录数。
6. 验证在线数据可使用新密钥读取后，再移除在线旧解密密钥。旧数据库备份仍需对应的历史密钥，离线妥善保留。

此操作轮换存储加密主密钥，不替换模型供应商签发的 API Key。发布版本仍固定当时的模型与能力配置；更换供应商 Key 后需重新发布对应 Agent。

## 调用额度与账本

- `AGENT_DAILY_MODEL_REQUEST_LIMIT`：每个用户每日模型请求上限，默认 1000，0 表示不设上限；按 UTC 日期重置。
- `AGENT_MAX_MODEL_REQUESTS_PER_RUN`：一次根执行及其所有子执行共享的模型请求预算，默认 100。
- `t_agent_usage_quota` 通过用户和日期唯一约束及条件 UPDATE 原子计数，跨线程、跨节点共用额度。计数单位是实际发起尝试的模型请求，不是根任务数量；失败尝试不返还，额度耗尽返回 429。
- 根 Agent、子 Agent、直接模型调用均使用该额度。直接调用模型也写入执行和每轮 Token 账本，以 `model_<配置ID>`、版本 0 表示，不装配 Agent 工具。
- `GET /v1/agent-console/quota` 返回当前用户的已用、上限、剩余额度；不能传入其他用户身份。额度为请求次数限制，不是货币金额预算。
- Java 业务调用 `invokeModel` 时需要传入可信的 `Caller`；HTTP 请求结构保持兼容。

## 取消与失败定位

执行记录页对运行中的根任务提供取消操作，对应 `POST /v1/agent-console/runs/{id}/cancel` 和 `ai:run:cancel` 权限。取消请求先写入数据库，本节点立即处理，其他节点每秒轮询接收。已结束的任务返回 409。已经发生的外部调用用量保留。

运行控制释放模型流、Harness、MCP、沙箱和会话互斥。SDK 会话异步清理结束后才允许同会话再次调用；只释放本次请求捕获的 owner/epoch 租约，不接管其他调用。

执行记录区分 `FAILED`、`CANCELLED`、`TIMED_OUT` 和 `INTERRUPTED`。节点启动时将超过执行超时加 30 秒且未更新心跳的遗留任务标记为中断，不修改仍在心跳的任务。本模块不自动重试和恢复未完成的工具副作用。

失败记录包含安全错误分类和 traceId，复用项目请求追踪。日志记录阶段、执行 ID、异常类型、代码栈位置及追踪 ID；不记录第三方异常原始消息、请求头或凭据。执行记录详情可按 traceId 定位日志。

## 数据库版本

启动时先执行 Agent 模块迁移，再运行既有实体初始化，最后补充动态权限、刷新角色缓存。`t_agent_schema_history` 记录版本、描述、SHA-256 校验和及完成时间。

迁移位于 `src/main/resources/db/agent`：V001 建立/接纳已有规范化表，V002 增加运维字段和额度表，V003 升级有效编码索引，V004 补齐九个菜单和 47 条动态接口权限，仅关联超级管理员。已完成文件不可修改，后续使用新版本文件。

MySQL 迁移使用同一连接上的命名锁。DDL 会隐式提交，执行器检查已有列和索引以恢复部分完成的升级；仅在版本完成后记录历史。权限迁移和对应版本记录在同一事务内提交，失败时回滚。升级失败或已执行文件内容变化时应用启动失败。

存在尚未复制到规范化表的旧 `ai_*` 数据时，启动会拒绝继续，需先按 `agentscope-framework-20261111.md` 执行历史数据迁移。自动版本管理不会替代历史数据复制或覆盖已有业务数据。

## 提交与验证

前后端分别提供 `AGENTS.md`、`scripts/install-hooks.sh`、`scripts/verify.sh` 与版本控制的 `.githooks`。首次克隆后安装钩子；已有其他 hooksPath 时安装脚本拒绝覆盖，需要接入原有钩子。

后端提交前检查暂存区的包结构、异常、动态权限和疑似凭据；Maven 默认测试自动检查 Controller 的 DTO/VO 边界、动态权限、兼容门面依赖和每个入口的数据库权限映射。推送前运行完整 `clean verify`。使用 JDK 21；Maven 不在 PATH 时通过 `MAVEN_BIN` 指定位置。

前端提交前检查差异和接口契约，推送前执行接口测试、Agent 模块 ESLint、类型检查和生产构建。钩子是本地工作流保护，服务端 CI 应调用相同验证脚本。

自动化测试使用隔离 H2、本地 HTTP 服务和确定的模型响应，不创建付费模型请求或云沙箱。真实 MySQL 部署、供应商及 E2B 仍需部署环境验收。

## 本次验证

后端验证共 165 项测试：159 项通过、6 项环境相关测试跳过，无失败或错误。覆盖真实 Spring 组件扫描和事务代理、并发额度、跨节点取消、取消后同会话重试、直接模型账本、超时分类、密文版本兼容与整批轮换回滚、旧库接纳、部分 DDL 恢复、迁移校验和及 47 条接口权限。最后补充的工具失败追踪和轮换期间的旧版本占位符编辑另行通过相关执行回归，推送钩子再次执行完整验证。

前端九项接口测试、Agent 模块 ESLint、类型检查和生产构建通过；消除登录组件经 API 聚合模块引入的循环依赖构建警告。本次未部署运行进程、未在线执行主密钥轮换，未调用真实厂商模型或创建云沙箱。数据库运维升级在新版本启动时执行。
